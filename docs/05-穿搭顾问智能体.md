# 穿搭顾问智能体

## 定义

穿搭顾问不是普通聊天机器人。它需要理解用户意图，选择并调用受控工具，再通过结构化动作改变 3D 数字人的试穿状态。

```text
自然语言需求
    ↓
意图规划器（demo / LLM adapter）
    ↓
查询商品 → 推荐尺码 → 检查搭配 → 应用试穿
    ↓
工具执行记录 + 3D 换装动作 + 自然语言回复
```

## 当前可演示能力

- 识别面试、通勤、约会、运动、校园和聚会场景。
- 识别正式、简约、休闲、活力和韩系风格。
- 提取预算和不希望使用的颜色。
- 缺少场景时主动追问，并从最近对话历史补全信息。
- 只从真实商品目录中选择有库存、符合预算的商品。
- 根据身高和体重调用尺码工具。
- 调用搭配规则工具，再向前端发送 `apply_outfit` 动作。
- 前端显示工具执行记录，并将结果应用到 3D 数字人。

## 工具白名单

| 工具                         | 输入                       | 输出                 |
| ---------------------------- | -------------------------- | -------------------- |
| `search_products`            | 场景、风格、预算、排除颜色 | 有库存的候选商品     |
| `recommend_size`             | 身高、体重、可用尺码       | 推荐尺码             |
| `check_outfit_compatibility` | 商品、场景、颜色           | 搭配规则结论         |
| `apply_outfit`               | 商品、尺码、颜色           | 前端可执行的换装命令 |

模型不能直接修改数据库或传入任意函数名。所有工具参数必须先经过 Pydantic 校验，价格、库存和尺码以服务端数据为准。

## API

`POST /api/v1/assistant/chat`

请求示例：

```json
{
  "message": "我下周面试，预算800元，正式但不要全黑",
  "history": [],
  "user_height_cm": 170,
  "user_weight_kg": 65
}
```

响应中的关键字段：

- `state`：需要补充信息、已完成或失败。
- `tool_events`：供前端展示的工具执行记录，不是模型内部思维过程。
- `outfit_action`：经过验证、可直接应用到数字人的换装命令。

## 接入真实大模型

当前默认 `LLM_PROVIDER=demo`，用于无密钥开发和稳定答辩。接入真实模型时：

1. 将 `LLM_PROVIDER` 设置为 `compatible`。
2. 配置兼容 chat-completions 协议的 `LLM_BASE_URL`、`LLM_MODEL` 和 `LLM_API_KEY`。
3. provider 只负责意图理解，不直接查询数据库或操作数字人。
4. 密钥只保存在本地 `.env` 或部署平台 Secret 中，不得提交到 Git。
5. 使用固定商品数据完成自动化测试，不让测试依赖外部模型服务。

环境变量预留在 `server/.env.example`：

```text
LLM_PROVIDER=demo
LLM_MODEL=
LLM_BASE_URL=
LLM_API_KEY=
```

示例中的基础地址应指向服务的版本根路径，代码会请求其 `/chat/completions` 端点。供应商不支持结构化 JSON 输出时，需要为该供应商增加独立 adapter，不要在业务工具中加入兼容分支。

## 答辩演示脚本

1. 输入“帮我搭一身衣服”，展示智能体主动追问场景。
2. 补充“下周面试，预算 800，正式但不要全黑”。
3. 展示查询商品、推荐尺码、搭配检查和应用试穿四个工具事件。
4. 展示 3D 数字人自动换装及推荐尺码。
5. 继续询问“换个颜色”，展示多轮交互；该步骤在接入完整 LLM adapter 后作为最终验收项。
