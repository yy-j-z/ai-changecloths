# 开发规范

## 环境

- Node.js 22，版本见 `.nvmrc`。
- Python 3.11，版本见 `.python-version`。
- Blender 4.2 LTS；全队使用相同大版本导出模型。
- 推荐 VS Code；文件统一 UTF-8、LF 行尾。

首次安装运行 `powershell -ExecutionPolicy Bypass -File scripts/setup.ps1`，提交前运行 `scripts/check.ps1`。

## Git 工作流

- `main`：答辩可用的稳定版本，只通过 PR 合并。
- `dev`：日常集成分支。
- 功能分支：`feat/avatar-editor`、`feat/garment-api`。
- 修复分支：`fix/avatar-clipping`。
- 分支使用英文、小写和短横线，避免空格及中文路径兼容问题。

提交使用 Conventional Commits，例如：

- `feat: add body morph controls`
- `fix: prevent garment clipping at large waist`
- `docs: document blender export settings`
- `test: cover size recommendation boundaries`

## 合并要求

- 一个 PR 只处理一个明确目标。
- 至少一名非作者成员评审。
- CI 中 lint、format、test、build 全部通过。
- 接口变化同步更新 OpenAPI 和相关测试。
- 新增 3D 素材必须登记 `docs/asset-licenses.csv`。

## Python 与 TypeScript

- Python 使用 Ruff 检查和格式化，函数与变量使用 `snake_case`。
- TypeScript 开启 strict，禁止无说明的 `any`。
- Vue 组件使用 PascalCase，组合式函数以 `use` 开头。
- 业务常量集中定义，不在页面中散落接口地址、错误码或模型路径。
